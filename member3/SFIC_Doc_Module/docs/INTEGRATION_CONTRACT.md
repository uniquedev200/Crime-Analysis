# ATLAS Integration Contract

**Status:** Signed / Frozen v1.0.0  
**Target Audience:** Dev 2 (API/Auth/Orchestration) and Dev 4 (Graph Database/Visualization)  
**Pipeline Version:** 0.1.0  
**Schema Version:** 1.0.0  

This document defines the frozen integration contracts between ATLAS (Dev 3) and external subsystems (Dev 2 and Dev 4), specifying the Graph Payload schema, Neo4j Cypher export syntax, Dev 2 HTTP communication adapter, and HTTP REST API endpoints.

---

## 1. Graph Payload Specification (Dev 4 Integration)

*(Reference: PLAN.md Section 4.6, `src/atlas/output/graph_payload.py`, `src/atlas/adapters/dev4_graph.py`)*

Dev 4 ingestion consumes this graph representation. The adapter layer in `src/atlas/adapters/dev4_graph.py` formats payloads into `generic`, `cytoscape`, `d3`, or `dev4` formats.

### 1.1 Node Contract

Every node in the graph follows the schema:

```json
{
  "node_id": "string",
  "label": "Person | Phone | Imei | Vehicle | Account | Organization | Location | Case | Event",
  "props": {
    "key": "value"
  },
  "case_ids": ["string"],
  "evidence_ids": ["string"],
  "canonical": true
}
```

#### Deterministic ID Generation Rules:
1. **Case Node (Case-Scoped):**
   - Node ID: `CASE:{case_id}`
   - Label: `Case`
   - Canonical: `true`
   - Props: `{"case_id": "{case_id}"}`

2. **Person Nodes (Case-Scoped):**
   - Node ID: `PERSON:{case_id}:{cluster_id}`
   - Label: `Person`
   - Canonical: `true`
   - Props: `{"name": "string", "role": "string", ...attributes}`

3. **Identifier Nodes (Global Across Cases):**
   - **Phone:** `PHONE:{e164}` (e.g., `PHONE:+919876543210`)
   - **IMEI:** `IMEI:{15_digits}` (e.g., `IMEI:867543029182736`)
   - **Vehicle:** `VEHICLE:{normalized}` (e.g., `VEHICLE:DL01AB1234`)
   - **Account:** `ACCOUNT:{ifsc_or_bank|""}:{number}` (e.g., `ACCOUNT::123456789012` or `ACCOUNT:SBIN:1234567890`)
   - Canonical: `true`

> **CRITICAL TRUST GATE:** Identifier nodes are created **ONLY** when `identifier_trust` is in `("strong", "confirmed")` or `confirmed_by` is set. Unconfirmed OCR identifiers **DO NOT** create identifier nodes and do not unify across documents or cases. They remain in the review queue until explicitly confirmed by an authorized human reviewer.

4. **Other Nodes:**
   - **Organization:** `ORGANIZATION:{case_id}:{slug}`, Label: `Organization`
   - **Location:** `LOCATION:{case_id}:{slug}`, Label: `Location`
   - **Event:** `EVENT:{event_id}`, Label: `Event`

### 1.2 Edge Contract

Every edge in the graph follows the schema:

```json
{
  "edge_id": "string",
  "type": "string",
  "src": "string",
  "dst": "string",
  "assertion": "stated | model_inferred | structured_record",
  "origin": "pdf_text | ocr | table_parser | text_file | json_file | model_inferred",
  "evidence_ids": ["string"],
  "case_ids": ["string"],
  "canonical": true,
  "props": {}
}
```

#### Edge Invariant Rules:
1. **Extracted Facts / Stated Relationships:**
   - Type matches `RelType` enum (`USES_PHONE`, `USES_DEVICE`, `OWNS_VEHICLE`, `HOLDS_ACCOUNT`, `ASSOCIATED_WITH`, `EMPLOYED_BY`, `LOCATED_AT`, `ALSO_KNOWN_AS`, `CALLED`, `TRANSFERRED_TO`).
   - Edges are created only between nodes that actually exist in the graph. If an unconfirmed OCR identifier node was omitted, relationships to it are omitted.
   - `canonical`: `true`.

2. **Resolution Suggestions (Cross-Case Candidates):**
   - Emitted as edges of type `CANDIDATE_MATCH`.
   - `canonical`: `false` (CRITICAL: Unapproved suggestions are NEVER canonical).
   - `assertion`: `model_inferred`.
   - `props`: contains `heuristic_rank`, `rank_note: "heuristic ordering, not a probability"`, `status`, and `explanation`.

3. **Approved Human Merges:**
   - Only created following explicit human review action `APPROVE_MATCH` or `MERGE`.
   - Emitted as edges of type `SAME_AS`.
   - `canonical`: `true`.
   - `assertion`: `stated`.
   - `props`: contains `audit_action_id` and `action_id`.

4. **Provenance Tracking:**
   - All nodes and edges carry `case_ids: string[]` and `evidence_ids: string[]` (sorted and deduplicated).

## 2. Neo4j Cypher Export Format

*(Reference: PLAN.md Section 4.6, `src/atlas/output/cypher_export.py`)*

ATLAS produces valid, standalone Neo4j Cypher text scripts using deterministic `MERGE` statements without requiring an active database connection:

```cypher
// Cypher export generated by ATLAS Dev 3
// Deterministic MERGE statements for nodes and relationships

// Nodes (3)
MERGE (n:Case {node_id: 'CASE:CASE-A-001'})
SET n.canonical = true,
    n.case_ids = ['CASE-A-001'],
    n.evidence_ids = [],
    n.case_id = 'CASE-A-001';
MERGE (n:Person {node_id: 'PERSON:CASE-A-001:vikram_singh'})
SET n.canonical = true,
    n.case_ids = ['CASE-A-001'],
    n.evidence_ids = ['M-01a2b3c4d5e6'],
    n.name = 'Vikram Singh',
    n.role = 'accused';
MERGE (n:Phone {node_id: 'PHONE:+919876543210'})
SET n.canonical = true,
    n.case_ids = ['CASE-A-001'],
    n.evidence_ids = ['M-07f8e9d0c1b2'],
    n.surface_text = '9876543210',
    n.trust = 'strong',
    n.value = '+919876543210';

// Edges (1)
MATCH (src {node_id: 'PERSON:CASE-A-001:vikram_singh'}), (dst {node_id: 'PHONE:+919876543210'})
MERGE (src)-[r:USES_PHONE {edge_id: 'R-112233445566'}]->(dst)
SET r.canonical = true,
    r.assertion = 'stated',
    r.origin = 'pdf_text',
    r.case_ids = ['CASE-A-001'],
    r.evidence_ids = ['R-112233445566'];
```

- Properties are escaped (special characters escaped with `\\`, `'`, `\n`).
- Nodes sorted deterministically by `node_id`, edges sorted deterministically by `edge_id`.

## 3. Dev 2 HTTP Client Adapter Contract

*(Reference: PLAN.md Section 4.7, 5.10, `src/atlas/adapters/dev2_http.py`)*

The `Dev2Client` communicates with Dev 2 services for user case permissions, review notifications, and evidence synchronization.

### 3.1 Client Configuration
- Base URL loaded from `config/defaults.yaml` (`dev2_base_url`) or environment variable `DEV2_BASE_URL`.
- Timeout loaded from `config/defaults.yaml` (`dev2_timeout_s: 30`).
- Bearer token authentication header if `DEV2_TOKEN` configured.

### 3.2 Methods & Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `get_case_permissions(user_name)` | `GET /users/{user_name}/permissions` | Queries authorized cases for a user |
| `notify_review_action(action)` | `POST /review/actions/notify` | Dispatches audited human review decision |
| `sync_evidence(case_id, payload)` | `POST /cases/{case_id}/evidence/sync` | Syncs extracted evidence records |

### 3.3 Error Mapping Contract
- HTTP `401` or `403` -> raises `atlas.errors.AuthorizationError`.
- HTTP `>= 400` or connection/timeout error -> raises `atlas.errors.ProviderError`.
- Partial writes or `{"success": false}` responses -> raises `atlas.errors.ProviderError`. No partial write is ever reported as success.

## 4. REST API Specification

*(Reference: PLAN.md Section 4.7, `src/atlas/api/`)*

Base URL: `/` (Default port `8000` via Uvicorn).

### 4.1 Headers and Authentication
- `X-Atlas-User`: Username header identifying caller.
- Default user if header omitted: `demo_analyst`.
- Stub authorization loads `config/demo_users.yaml` (`allowed_cases` per user).
- **Zero Existence Leak:** Unauthorized access to any case endpoint returns HTTP `403 Forbidden` immediately, without inspecting or leaking whether the case directory exists.

### 4.2 Endpoints Reference

#### 1. POST /cases/{case_id}/documents
Uploads evidence document (PDF, PNG, JPG, CSV, XLSX, TXT, JSON). Computes SHA-256 and stores immutable original.
- **Request:** `multipart/form-data` with `file` part.
- **Response `201 Created`:**
```json
{
  "doc_id": "DOC-9f8e7d6c5b4a",
  "file_sha256": "9f8e7d6c5b4a...64_hex_digits",
  "state": "queued"
}
```

#### 2. POST /cases/{case_id}/jobs
Starts background pipeline execution for the case.
- **Request Body (optional):**
```json
{
  "doc_ids": ["DOC-9f8e7d6c5b4a"]
}
```
- **Response `202 Accepted`:**
```json
{
  "job_id": "JOB-RUN-20261016T120000Z-a1b2c3",
  "state": "queued"
}
```

#### 3. GET /jobs/{job_id}
Queries execution status and progress of a background job.
- **Response `200 OK`:**
```json
{
  "job_id": "JOB-RUN-20261016T120000Z-a1b2c3",
  "state": "completed | completed_with_warnings | running | queued | failed",
  "progress": 1.0,
  "warnings": []
}
```

#### 4. GET /cases/{case_id}/results/latest
Retrieves the complete, validated `CaseResult` Pydantic model output for the most recent run.
- **Response `200 OK`:** Full `CaseResult` JSON object (`schema_version: "1.0.0"`, `state`, `documents`, `mentions`, `relationships`, `events`, `aggregates`, `review_items`, `rejections`, `warnings`).

#### 5. GET /cases/{case_id}/review-items
Retrieves list of actionable human review items.
- **Response `200 OK`:**
```json
[
  {
    "review_id": "REV-01a2b3c4d5e6",
    "case_id": "CASE-A-001",
    "kind": "low_trust_identifier",
    "target_ids": ["M-123456789abc"],
    "detail": "OCR phone number requires confirmation",
    "status": "open",
    "resolution": null
  }
]
```

#### 6. GET /cases/{case_id}/suggestions
Retrieves authorization-filtered cross-case candidate entity resolution suggestions.
- **Response `200 OK`:**
```json
[
  {
    "suggestion_id": "SUG-998877665544",
    "case_id": "CASE-A-001",
    "mention_id": "M-123456789abc",
    "candidate_entity_id": "PERSON:CASE-B-002:c1",
    "candidate_case_id": "CASE-B-002",
    "status": "candidate | needs_review | ambiguous | no_match",
    "heuristic_rank": 0.85,
    "rank_note": "heuristic ordering, not a probability",
    "signals": [
      {
        "kind": "exact_identifier",
        "polarity": "supports",
        "detail": "Shared confirmed phone +919876543210",
        "sources": []
      }
    ],
    "explanation": "Exact strong identifier match with high name similarity.",
    "requires_human_decision": true
  }
]
```

#### 7. POST /review/actions
Submits an authorized, hash-chained review decision.
- **Request Body:**
```json
{
  "type": "CONFIRM_IDENTIFIER | CORRECT_IDENTIFIER | APPROVE_MATCH | REJECT_MATCH | MERGE | SPLIT | RESOLVE_ITEM",
  "reason": "Verified digits on document page 1 crop",
  "target_ids": ["M-123456789abc"],
  "payload": {},
  "case_id": "CASE-A-001"
}
```
- **Response `200 OK`:**
```json
{
  "state": "applied",
  "success": true,
  "action_id": "ACT-1234567890ab",
  "message": "Action CONFIRM_IDENTIFIER applied and audited successfully"
}
```

#### 8. GET /cases/{case_id}/graph
Retrieves graph payload with optional format conversion (`format=generic|cytoscape|d3|dev4`) and optional Cypher export (`export_cypher=true`).
- **Response `200 OK`:**
```json
{
  "case_id": "CASE-A-001",
  "state": "completed",
  "format": "generic",
  "nodes": [...],
  "edges": [...],
  "cypher": "// Cypher script when export_cypher=true"
}
```

#### 9. GET /cases/{case_id}/evidence/{mention_id}
Inspects exact quote, transcript coordinate/bbox, origin, OCR scores, and allowed actions for a mention.
- **Response `200 OK`:**
```json

  "quote_status": "verified",
  "source": {
    "doc_id": "DOC-9f8e7d6c5b4a",

    "file_sha256": "9f8e7d...",
```

Public health and readiness check.
